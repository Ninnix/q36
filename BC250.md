# Q36 on the AMD BC-250

This is the minimal setup for Q36 Vulkan inference on the AMD BC-250
(`1002:13fe`, Cyan Skillfish, 16 GB unified GDDR6). Q36 uses Mesa RADV, not
ROCm. The stock 24-CU board works; the 40-CU unlock is optional.

The board needs real cooling and a suitable power supply before sustained
inference. See the community [hardware prerequisites][prerequisites] for power,
cooling, storage, and display setup.

## 1. Install Linux and RADV

Use a recent Linux distribution with Mesa 25.1.3 or newer. Avoid kernels
6.15.0 through 6.15.6 and 6.17.8 through 6.17.10: they have known BC-250 GPU
initialization failures. The community [kernel guide][kernel] tracks current
working versions.

Install a C toolchain, Vulkan headers and loader, RADV, `vulkaninfo`, and
`glslangValidator`. For example:

```sh
# Arch Linux / CachyOS
sudo pacman -S --needed base-devel mesa vulkan-radeon vulkan-icd-loader \
  vulkan-headers vulkan-tools glslang

# Fedora
sudo dnf install gcc make mesa-vulkan-drivers vulkan-loader-devel \
  vulkan-tools glslang

# Debian / Ubuntu; verify that the installed Mesa is new enough
sudo apt install build-essential libvulkan-dev mesa-vulkan-drivers \
  vulkan-tools glslang-tools
```

Verify that Vulkan is using the hardware RADV device, not `llvmpipe` or
AMDVLK:

```sh
vulkaninfo --summary
vulkaninfo | grep -E 'driverName|deviceName|vendorID|deviceID'
```

Expected values include `radv`, `RADV GFX1013`, vendor `0x1002`, and device
`0x13fe`. Remove `nomodeset` from the permanent kernel command line after OS
installation; leaving it set disables GPU acceleration. See the community
[RADV guide][radv] if the device is missing.

## 2. Set the UMA split to 512 MB

The split is a minimum reservation, not a fixed ceiling. A 512 MB split leaves
most memory available to Linux while RADV grows GPU usage into the unified
pool.

The preferred method does not flash the BIOS:

```sh
git clone https://github.com/fanoush/bc250_memcfg
cd bc250_memcfg
make
sudo ./bc250memcfg UMA_SIZE 512
sudo reboot
```

The value is stored in CMOS and does not need to be applied at every boot. If
the board already has firmware with the Chipset menu unlocked, the equivalent
settings are:

```text
Integrated Graphics -> UMA Mode -> UMA_SPECIFIED
Integrated Graphics -> UMA Frame Buffer Size -> 512 MB
```

Do not flash modified firmware only for this setting. Read the community
[VRAM guide][vram] before changing an existing split or firmware.

## 3. Increase GPU-visible memory

The default TTM limit is too small for Q36's resident model. Add these kernel
parameters to the existing boot command line:

```text
amdgpu.gttsize=14750 ttm.pages_limit=3959290 ttm.page_pool_size=3959290
```

On a GRUB system, edit `/etc/default/grub`, append the parameters to the
existing `GRUB_CMDLINE_LINUX_DEFAULT`, then regenerate the configuration:

```sh
# Debian / Ubuntu
sudo update-grub

# Arch Linux
sudo grub-mkconfig -o /boot/grub/grub.cfg

# Fedora
sudo grub2-mkconfig -o /boot/grub2/grub.cfg

sudo reboot
```

Other boot loaders need the same three parameters applied by their native
configuration mechanism. Do not enable `amd_iommu=on`; it is known to break
the BC-250. After reboot, verify the active command line and memory setup:

```sh
cat /proc/cmdline
sudo dmesg | grep -Ei 'GTT|TTM|VRAM'
cat /sys/module/ttm/parameters/pages_limit
cat /sys/module/ttm/parameters/page_pool_size
```

The [akandr/bc250 guide][akandr] has a deeper GTT/TTM investigation, including
late `systemd-tmpfiles` overrides that can silently replace the boot-time
limits. On Fedora 43 with kernel 6.18.9 it reports a different setup:
`ttm.pages_limit=4194304` exposes a full 16 GiB GTT without `amdgpu.gttsize`,
which that guide describes as deprecated. Treat this as a kernel-specific
alternative, not an addition to the Q36 settings above, and always verify the
live sysfs values.

## 4. Install the GPU governor

Without a governor the GPU normally remains at 1500 MHz. The current community
default is `cyan-skillfish-governor-smu`; it controls clocks through the SMU
and does not require a patched kernel.

```sh
# Arch Linux / CachyOS, using an installed AUR helper
paru -S cyan-skillfish-governor-smu
sudo systemctl enable --now cyan-skillfish-governor-smu.service

# Fedora
sudo dnf copr enable filippor/bazzite
sudo dnf install cyan-skillfish-governor-smu
sudo systemctl enable --now cyan-skillfish-governor-smu.service
```

For Debian, Ubuntu, Bazzite, configuration, and stability testing, follow the
community [governor guide][governor]. Start with its conservative curve. Do not
run two GPU governors at once, and do not increase clocks or voltage until the
board is stable under sustained load.

Verify the service and watch temperature and clock changes while Q36 runs:

```sh
systemctl status cyan-skillfish-governor-smu
sensors
```

The Q36 benchmarks used a 500-2000 MHz range and an 85 C thermal ceiling. That
is benchmark context, not a guarantee that every board and cooling setup is
stable at the same settings.

## 5. Build and run Q36

Download the resident Q2 model and build the checked BC-250 target:

```sh
./download_model.sh q2-imatrix
make vulkan-bc250 -j"$(nproc)"
./q36 --vulkan -p "Explain radix trees."
```

Startup should report the Vulkan device and `BC-250 fast path`. The Q2 weights
use roughly 10-11 GB. The higher-quality Q2-Q4 model is roughly 13 GB and
should use SSD streaming on this 16 GB machine:

```sh
./download_model.sh q2-q4-imatrix
./q36 --vulkan --ssd-streaming \
  -m gguf/Qwen3.6-35B-A3B-Layers34-39Q4KExperts-OtherExpertLayersIQ2XXSGateUp-Q2KDown-Q8Rest-imatrix.gguf \
  -p "Hello"
```

Run only one large model process at a time. If the resident model fails to
allocate, first check the active UMA split and kernel parameters rather than
reducing the model's expected memory.

## 6. Optional 40-CU unlock

Q36 does not require the experimental 40-CU kernel patch. The repository's
published BC-250 benchmarks used it, so a stock 24-CU board will be slower.

The unlock is temporary and opt-in through
`amdgpu.bc250_cc_write_mode=3`, but it needs a patched kernel and increases
power draw sharply. Use the community [40-CU guide][unlock] and improve cooling
before enabling it. Rebooting a patched kernel without the parameter returns
the GPU to 24 CUs.

## 7. Optional ACE compute queues

The [BC-250 GFX1013 compute queue fix][ace-fix] provides matching kernel and
Mesa/RADV patches that repair and expose the board's ACE queues. Install both
halves as described by that project; using its patched Mesa without its kernel
patch can hang the GPU.

On a BC-250 whose kernel and RADV expose a compute-only queue family, Vulkan
automatically submits through one ACE queue. It falls back to the original
graphics queue when that family is absent. Set `Q36_VK_ACE=0` to force the
fallback for comparison or troubleshooting. QuarkStar does not stripe one
inference stream over multiple ACE queues: its dependent dispatches must stay
ordered, and queue handoffs would not add parallel work.
